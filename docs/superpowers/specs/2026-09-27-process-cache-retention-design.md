# 进程解析降频与七天数据保留设计

## 目标

在不改变 NetAssess 现有统计口径和进程实例标识方式的前提下：

1. 消除每个 ETW 网络事件都执行一次进程创建时间查询的高开销路径。
2. 为长期运行的主进程统计和连接明细增加可预测的数据回收规则。
3. 连接明细达到 100000 条上限后，允许新连接通过淘汰最老历史连接继续进入。

成功标准：高频事件在一秒校验窗口内复用进程缓存；运行中进程不因空闲被清理；已结束且最后活动超过七天的进程及连接被删除；容量已满时批量淘汰历史连接，而全部连接仍活跃时继续安全丢弃并计数。

## 进程解析缓存

`ProcessInfoCache::Resolve` 接收 `std::chrono::steady_clock::time_point now`。每个成功识别的 PID 缓存进程信息、上次成功或失败校验时间以及连续失败次数。

- 第一次看到 PID 时仍执行完整进程查询。
- 缓存命中且距离上次校验不足一秒时，直接返回缓存信息。
- 达到一秒后查询当前创建时间。创建时间相同则刷新校验时间并继续使用缓存。
- 创建时间不同则完整查询当前 PID，并用新的 `ProcessInstanceId` 替换缓存。
- 查询创建时间失败时沿用现有的连续失败容忍规则，但失败次数最多每秒增加一次，避免网络事件速率决定重试速度。
- 受限进程的完整查询同样最多每秒重试一次。

ETW 回调在解码后立即取得一个 `steady_clock` 时间点，并同时用于进程解析和连接活动时间，避免同一事件使用不一致的时间基准。

该方案保留 PID + 创建时间标识。代价是 PID 在校验间隔内结束并被复用时，最多约一秒的事件可能暂时归入旧实例；这是已确认的性能与精度折中。

## 主窗口存活查询去重

主窗口每次刷新时，以 `ProcessInstanceId` 为键缓存本轮 `RefreshAlive` 结果。同一进程即使因为 TCP、UDP 或多个应用协议出现多行，也只查询一次。缓存仅在单次刷新内有效，不改变下一秒的存活判断。

## 活动时间记录

`TrafficEvent` 增加 `observed_at`，主进程聚合条目保存 `last_activity`。ETW 监视器为主进程事件和连接事件写入同一个单调时钟时间点。

连接聚合器继续使用已有的 `last_activity`。累计字节、速度基线和活动时间都在现有锁保护下更新。

## 七天保留与清理调度

主窗口负责低频调度，每十分钟执行一次清理：

1. 从主进程聚合器和连接聚合器按进程汇总最近活动时间；只有进程的最新活动时间早于 `now - 7 days` 时，才把该 `ProcessInstanceId` 列为候选。
2. 合并并去重候选进程。
3. 在聚合器锁之外，每个候选进程仅调用一次可区分“运行中 / 已结束 / 查询失败”的存活探测。
4. 只把确认已经结束的进程传回两个聚合器统一删除。

清理删除该进程的全部主统计条目、连接条目和连接速度快照基线。运行中的进程无论空闲多久都保留。查询失败按“未确认结束”处理，本轮不删除，下一轮再检查。

候选收集和删除分别持有短期锁；Windows 进程查询绝不在聚合器锁内执行，避免阻塞 ETW 写入。

“清零统计”保持现有语义：立即删除所有数据和速度基线，并重置明细丢弃计数。

## 连接容量淘汰

连接聚合器默认容量仍为 100000。新连接到来且容量已满时：

1. 扫描当前连接，选择最后活动时间早于 `now - 5 seconds` 的历史连接。
2. 按最后活动时间从旧到新选择一批，批量大小为容量的 5%，且至少为一条。
3. 删除所选连接；如果某个进程已无连接，同时删除它的连接速度快照基线。
4. 插入当前新连接。

批量淘汰把全表扫描成本摊销到后续约 5% 容量的新连接上，避免满容量后每个新连接都扫描全表。

如果没有可淘汰的历史连接，说明当前容量全部由最近五秒活跃连接占用；此时维持现有行为，丢弃新连接并以饱和加法增加“明细丢弃”计数。

容量淘汰不修改七天保留规则：七天是正常清理期限，容量压力下允许更早淘汰历史连接。

## 接口调整

- `ProcessInfoCache::Resolve(pid, fallback_observation_id, now)`：增加当前单调时间。
- `TrafficEvent`：增加 `observed_at`。
- `ProcessInfoCache`：保留供界面显示使用的布尔存活查询，并增加返回三态结果的清理专用存活探测；查询失败不等同于进程结束。
- `TrafficAggregator`：增加按进程最新活动时间生成候选和按进程集合删除的接口。
- `ConnectionAggregator`：增加候选进程查询和按进程集合删除接口；内部增加批量历史淘汰。
- `MainWindow`：增加十分钟清理调度时间，并在刷新时执行到期清理。

接口只服务当前需求，不增加用户可配置项或新的设置窗口。

## 错误处理与并发

- 所有时间比较使用 `steady_clock`，不受系统时间调整影响。
- 进程查询失败不会触发数据删除。
- 清理与 ETW 添加事件通过聚合器现有互斥锁串行化。
- 容量淘汰只在插入新连接且已满时发生，并在连接聚合器锁内完成。
- 字节累计和丢弃计数继续使用饱和加法。

## 测试

新增或扩展单元测试覆盖：

- 一秒窗口内缓存命中不调用进程 API。
- 一秒到期后重新校验创建时间。
- PID 复用后生成新的进程实例。
- 失败和受限进程的重试按时间而不是事件数量发生。
- 主窗口单次刷新对同一进程只做一次存活查询。
- 七天前仍运行的进程不删除。
- 七天前已结束的进程从主统计、连接统计和速度基线删除。
- 七天边界值不提前删除。
- 满容量时批量删除最老历史连接并接受新连接。
- 全部连接活跃时丢弃新连接并增加计数。
- 清零行为保持不变。

# 进程连接明细设计

## 1. 目标与范围

在现有 Windows 进程流量监控器中增加连接级视图。用户在主列表中右键任意进程行，选择“查看连接明细”，可查看该进程的本机 IP 和端口、对端 IP 和端口、传输层协议、端口推断应用协议、方向、双向累计和实时速度。

本功能不解析报文内容，不做 DNS 反查，不展示 TCP 连接状态机，不增加导出或持久化。现有主列表的聚合口径和操作保持不变。

## 2. 交互设计

### 2.1 打开方式

- 主 ListView 在数据行上响应右键，显示仅包含“查看连接明细”的上下文菜单。
- 菜单作用于整个进程实例，不只限于被右键行的协议类别。
- 一个进程实例最多对应一个已打开的明细窗口。重复打开时激活已有窗口。
- 明细窗口为可缩放的非模态顶层受拥有窗口；允许同时查看多个进程。
- 标题格式为“`进程名 — PID <pid> — 连接明细`”。

### 2.2 明细列

明细 ListView 按以下顺序显示：

1. 状态；
2. 方向；
3. 传输层；
4. 推断应用协议；
5. 本机 IP；
6. 本机端口；
7. 对端 IP；
8. 对端端口；
9. 上行累计；
10. 上行速度；
11. 下行累计；
12. 下行速度。

IP 地址和端口分列显示。IPv4 使用点分十进制，IPv6 使用 Windows `InetNtopW` 生成的标准压缩文本。各列支持点击列头切换升序和降序；IP 地址按二进制地址值排序，端口按数值排序，不使用格式化文本排序。

默认按上下行速度之和降序。刷新时保留用户排序、选中行和可见位置。

### 2.3 方向和状态语义

- 只有上行累计非零：方向显示“上行”。
- 只有下行累计非零：方向显示“下行”。
- 双向累计都非零：方向显示“双向”。

网络流量事件无法对 TCP 断开和 UDP 的“结束”给出统一且无丢失的保证，因此不声称连接已关闭：

- 进程存活且最近 5 秒内有流量：“活跃”。
- 进程存活但超过 5 秒无流量：“历史”。
- 进程实例已退出：“进程已结束”。

明细窗口约每秒刷新。关闭明细窗口不删除统计。主窗口“清零统计”同时清空主汇总、连接明细、速度基线和明细丢弃计数。主窗口销毁时先关闭所有明细窗口。

## 3. 事件解码与端点方向

### 3.1 地址类型

新增值类型 `IpAddress`：

- 地址族：IPv4 或 IPv6；
- 16 字节定长存储；IPv4 只使用前 4 字节，其余置零；
- 支持稳定比较，用于映射键和排序；
- 不保存指向 ETW payload 的指针。

`DecodedNetworkEvent` 扩展为包含源地址和目标地址。`EventLayout` 扩展 `saddr` 和 `daddr` 字段布局。TDH 布局发现要求：

- IPv4 地址宽度必须为 4 字节；
- IPv6 地址宽度必须为 16 字节；
- PID 和 size 必须为 4 字节；
- sport 和 dport 必须为 2 字节；
- 任一必需字段缺失、重复、宽度错误或越界时，目标 send/receive 事件计入解析失败，不提交部分数据。

非 TCP/UDP provider、非 send/receive opcode 和无效 header-width 事件仍属于 `Ignored`，不缓存无效布局，不增加解析失败。

### 3.2 本机和对端转换

- send：`local = source address:port`，`remote = destination address:port`。
- receive：`local = destination address:port`，`remote = source address:port`。

该转换是纯函数，在 ETW 回调后、聚合前执行。回环、组播、广播或本机多网卡地址不做特殊猜测，严格使用事件的源/目的和方向。

## 4. 聚合设计

### 4.1 双聚合器

现有 `TrafficAggregator` 保留，继续生成主列表的进程级统计。新增 `ConnectionAggregator`，两者由同一个成功解码的 ETW 事件更新：

1. 解码 PID、字节数、协议、方向、源/目地址和端口；
2. 解析稳定进程实例和名称；
3. 根据方向推断应用协议；
4. 更新进程级聚合器；
5. 转换本机/对端后更新连接级聚合器。

连接键为：

`ProcessInstanceId + TransportProtocol + ApplicationProtocol + local IpAddress:port + remote IpAddress:port`

同一连接键的 send 和 receive 事件更新同一项的上行和下行计数。字节累加使用与主聚合器相同的 64 位饱和语义。

### 4.2 快照、速度和活动时间

`ConnectionAggregator::Snapshot(now)` 返回不可变快照：

- 累计字节、速度基线和无正时间差行为与 `TrafficAggregator` 一致；
- 首次快照速度为 0；
- 没有新字节时上/下行速度回到 0；
- 每项保存最后一个事件的单调时间；
- 快照时由显示层用 `now - last_activity <= 5s` 判定“活跃/历史”。

事件的 ETW QPC 时间不与 `steady_clock` 直接混用。聚合提交时由消费线程记录 `steady_clock::now()` 作为活动时间；测试可直接传入确定时间点。

### 4.3 容量上限

全局最多保留 `100,000` 个唯一连接键。

- 已存在的键始终允许继续累加。
- 达到上限后，新键不进入连接明细，每个被丢弃的新键事件使 64 位“明细丢弃”计数饱和增加。
- 主进程统计仍正常更新。
- 不自动淘汰旧键，避免用户正在查看的历史无提示消失。
- `Clear()` 清空映射、速度基线和丢弃计数，恢复接收新键。

状态栏分别显示 ETW `EventsLost`、`RealTimeBuffersLost`、解析失败和明细丢弃；不将这些不同单位相加。

## 5. 线程与窗口生命周期

- ETW 消费线程解码后依次短时更新两个聚合器，不调用任何 GUI API。
- UI 线程的主定时器获取主快照，并为每个已打开的明细窗口获取相应进程的连接快照。
- 明细聚合器支持按 `ProcessInstanceId` 复制快照，不要求 UI 每秒复制其他进程的全部明细。
- 聚合器映射受短时互斥保护；格式化、存活检查、排序和 ListView 更新都在锁外执行。
- 明细窗口注册表由 UI 线程独占，键为 `ProcessInstanceId`；窗口销毁时删除自身注册项。
- 清零不关闭明细窗口；下一次刷新显示空表。

## 6. 既有缺陷与设计裁决

### 6.1 ETW 丢失计数竞态

必须在本功能上线前修复已复现的 Release 并发测试失败：`events_lost()` 不得在 QUERY 更新和返回值读取之间释放保护，使并发 STOP 覆盖本次调用应返回的值。修复必须有稳定重现测试，并在 Release 下重复运行。

`EventsLost` 和 `RealTimeBuffersLost` 仍分别暴露，不相加。QUERY 和完成型 STOP 都更新最终计数。

### 6.2 始终不可查询的 PID 复用

如果两个先后进程使用同一 PID，且 Windows 对它们的所有身份查询始终失败，仅依赖网络事件无法区分“一个长期进程”和“PID 已换代”。

本设计保留稳定 fallback 身份，不按每 N 个事件强制拆分，因为后者会将一个长期受限进程错拆为多个实例。查询后来恢复成功时，必须改用真实创建时间并正确识别 PID 复用。README 必须明确这一极端限制，不得声称持续失败时可在固定事件数内识别换代。

## 7. 错误处理

- 目标网络事件缺少地址字段或宽度错误：整条事件计入解析失败，两个聚合器都不更新。
- IP 文本格式化失败：显示“无效地址”，二进制键和统计仍保留。
- 连接明细达到上限：不影响主汇总，状态栏显示饱和丢弃计数。
- 窗口创建失败：主窗口保持可用，显示 Win32 错误码，不清除统计。
- ETW STOP 失败：保留会话所有权以便重试，不允许在未清理的旧会话上新建会话。
- 回调内部异常：不跨越 Win32 C 回调边界，记录错误并请求安全停止。

## 8. 模块修改

- `src/traffic_types.h`：新增 IP、端点、连接键、事件和快照值类型。
- `src/etw_decoder.h/.cpp`：扩展地址字段布局和 payload 解码。
- `src/connection_aggregator.h/.cpp`：新增线程安全连接聚合器。
- `src/etw_monitor.h/.cpp`：向两个聚合器提交同一解码事件，修复丢失计数并发返回竞态。
- `src/connection_window.h/.cpp`：新增连接明细窗口和可测试的行构建/排序逻辑。
- `src/main_window.h/.cpp`：上下文菜单、明细窗口注册表、定时刷新、清零和关闭协调。
- `src/formatting.h/.cpp`：IP 和连接状态/方向文本格式化。
- `CMakeLists.txt`：编译新模块，继续仅支持显式 Visual Studio/MSVC/x64 配置。
- `README.md`：文档化右键用法、列、活跃语义、容量上限、统计口径和 PID 极端限制。
- `tests/unit_tests.cpp`：保持单一无第三方测试入口，覆盖新纯逻辑和注入边界。

## 9. 自动化测试

至少覆盖：

- IPv4 send/receive 的源/目地址和端口解码；
- IPv6 send/receive 的 16 字节地址解码和文本格式化；
- 地址缺失、重复、宽度错误和 payload 越界；
- 未知 provider、非 send/receive 和 header 事件不增加解析失败；
- send 和 receive 正确转换本机/对端；
- 同一端点对的双向事件合并为一行；
- 同 IP 不同端口、同端口不同 IP、TCP/UDP、应用协议和进程实例彼此隔离；
- 双向饱和、首次速度、已知时间差、无正时间差、无新流量归零和清零；
- 5 秒活跃边界和进程已结束优先级；
- 100,000 个唯一键后拒绝新键，但继续更新旧键；丢弃计数和 Clear 重置；
- 方向文本、数值排序、二进制 IP 排序和默认组合速度排序；
- 主列表任意协议行均解析到同一 `ProcessInstanceId` 明细窗口；
- 一个合成 `EVENT_RECORD` 经真实 `EventRecordCallback`、解码器、进程解析、协议推断后，同时更新主聚合器和连接聚合器；
- ETW QUERY 与 STOP 并发时，getter 返回本次调用查询到的值，Release 测试重复运行不间歇失败。

## 10. 手工验收

在 Windows Server 2016 或更高版本 Desktop Experience x64 上，以管理员运行 Release：

1. 由已知 PID 的 PowerShell 分别发起 IPv4/IPv6 HTTPS 请求和 UDP DNS 查询。
2. 主列表对应进程的 TCP/UDP 累计和速度正常。
3. 右键该进程任意行打开明细，核对本机/对端 IP、端口、方向和协议。
4. 反复请求时累计增长、速度为正；停止后速度归零，5 秒后状态转为“历史”。
5. 退出测试进程后，明细行显示“进程已结束”且累计保留。
6. 同时打开两个进程的明细窗口，确认独立刷新；重复打开同一进程只激活旧窗口。
7. 点击列头验证排序，缩放窗口验证 ListView 布局，观察 Unicode 进程名和 IPv6 文本。
8. 点击清零，确认主列表和所有明细窗口清空，采集仍在运行。
9. 关闭主窗口，确认所有明细窗口关闭，进程退出且无 `NetAssess-*` ETW 会话残留。
10. 记录 `EventsLost`、`RealTimeBuffersLost`、解析失败和明细丢弃计数；任一非零值都随验收结果报告。

## 11. 已知限制

- 应用协议仍只按端口推断。
- “活跃/历史”表示最近流量，不表示 TCP 状态机或 UDP 会话是否真正关闭。
- 连接累计从开始采集时起，不恢复历史。
- ETW 丢失、解析失败或连接明细容量达限时，明细与主累计可能是实际流量的下界。
- 一个连接键被重新使用时，在清零前继续聚合到同一行；本功能不追踪 TCP 连接序列号或独立会话 ID。
- 对于持续不可查询且发生 PID 复用的进程，不同生命周期的流量可能合并。

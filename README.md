# NetAssess Windows 进程流量监视器

NetAssess 是一个原生 x64 Windows GUI 程序，使用 ETW 实时统计本机进程的 TCP/UDP 上下行流量。它不解析报文内容，不需要抓包驱动或第三方运行库。

## 支持范围与权限

- 支持 Windows Server 2016、2019、2022、2025 及后续保持兼容的版本，要求 Desktop Experience。
- 仅支持 x64；不支持 Server Core、Windows 容器、ARM64、x86 或远程主机。
- 程序清单声明了 `requireAdministrator`。启动时 Windows 会自动显示 UAC 提升提示；取消提升则程序不启动。

## 构建与测试

要求 Visual Studio 2022 Professional、MSVC、Windows SDK 和 CMake。项目会拒绝非 MSVC 编译器、非 Visual Studio 生成器，以及未显式指定或不是 `x64` 的生成器平台；因此即使 IDE 默认选择 x64，也必须在配置时传入 `-A x64`。在仓库根目录打开 PowerShell，执行：

```powershell
$netAssessCmake = 'D:\Program Files\Microsoft Visual Studio\2022\Professional\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
& $netAssessCmake -S . -B build -A x64
& $netAssessCmake --build build --config Debug
& $netAssessCmake --build build --config Release
& $netAssessCmake --build build --config Debug --target RUN_TESTS
```

Release 可执行文件位于 `build/Release/NetAssess.exe`。这是 Windows 子系统程序，不会打开控制台窗口。

Release 使用 `/MT` 静态链接 MSVC 运行库，无需另外安装 Visual C++ Redistributable。发布更新时应重新构建，以包含新版运行库的修复。

## 使用方法

1. 运行 `build/Release/NetAssess.exe` 并在 UAC 提示中允许提升。主窗口打开后会自动开始采集。
2. “开始采集/停止采集”用于启停 ETW 采集。停止再启动不会清除已有累计值。
3. “清零统计”用于清空所有历史行、累计值和速度基线，但不停止采集。
4. “进程名筛选”不区分大小写，只影响当前显示，不影响后台统计。
5. 默认按上行速度与下行速度之和降序显示；点击列头可按该列排序，再次点击切换升序/降序。
6. 当前排序列的列头显示 Windows 原生升序/降序箭头。窗口初始、筛选条件变更或点击列头后，列表自动置顶；手动使用滚动条、鼠标滚轮或键盘离开顶部后，定时刷新会保持当前顶部行和选择项，手动回到第一行则恢复自动置顶。
7. 点击“导出 CSV”可保存当前筛选、当前排序后的全部可见行（而非只导出选中行或屏幕中的行）。文件使用 UTF-8 BOM、当前列顺序和标准 CSV 转义；取消保存不报错，写入或关闭失败会显示 Windows 错误码。
8. 退出程序时会停止并清理本程序创建的私有 ETW 会话。

表格每秒刷新一次，共有九列：

| 列 | 含义 |
|---|---|
| 进程名 | 可执行文件名；无法查询时显示“受限进程 (PID)” |
| PID | Windows 进程标识符 |
| 状态 | “运行中”或“已结束”；进程结束后累计行保留至清零 |
| 传输层协议 | TCP 或 UDP |
| 推断应用协议 | 依据传输层和端口推断的应用协议 |
| 上行累计 | 采集开始后 ETW 报告的发送 IP 字节数 |
| 上行速度 | 当前发送速率 |
| 下行累计 | 采集开始后 ETW 报告的接收 IP 字节数 |
| 下行速度 | 当前接收速率 |

状态栏分别显示当前采集状态、ETW 事件丢失数、实时缓冲区丢失数、解析失败事件数和最近错误。会话启动失败时，窗口仍保持可操作；请根据系统错误码排查后重试，不要停止其他 ETW 会话。

## 进程快捷操作

在主表中选中或右键一个进程实例，右键菜单依次提供“查看连接明细”、“打开文件所在位置”和“结束进程”。键盘上下文菜单与鼠标右键作用于同一目标行。

- “打开文件所在位置”会让资源管理器选中该进程的 EXE 文件，而非仅打开目录。已结束、受保护或无法读取路径的进程不会猜测路径；查询或启动失败会显示操作名称和 Windows 错误码。
- “结束进程”先显示包含进程名和 PID 的确认框。确认后程序重新读取进程创建时间，只有 PID 和创建时间同时仍与列表行匹配才调用 `TerminateProcess`；PID 已复用或进程已退出时拒绝操作。它只请求结束这个进程，不会递归结束子进程树。访问被拒绝、受保护进程和其他失败会显示 Windows 错误码；成功请求结束后，最终状态仍以随后存活检查为准。

## 统计口径

- 每行按“进程实例（PID + 创建时间）+ TCP/UDP + 推断应用协议”聚合，因此 PID 被复用时不会并入旧进程数据。
- 累计值只包含开始采集后收到的 ETW IP 网络事件字节，不是网卡线速字节，也不包含所有链路层开销。
- 界面约每秒取一次快照。速度是两次快照的字节差除以单调时钟的实际时间差，并非假定间隔永远恰好为 1.000 秒。首次快照、清零后的首次快照、无正时间差或计数回退时，速度显示为 0。
- 字节数使用 1024 进制格式化为 B/KB/MB/GB/TB，速度显示为 B/s、KB/s、MB/s、GB/s 或 TB/s。
- “事件丢失”对应 ETW 的 `EventsLost`，“实时缓冲区丢失”对应 `RealTimeBuffersLost`；任一计数非零都表示部分事件可能已无法补回，此时累计值只是实际流量的下界。两个计数分别展示，不相加。“解析失败”只统计目标 TCP/UDP 收发事件的 schema 或 payload 错误，未知 provider 和 connect/disconnect 等非目标 opcode 会被静默忽略。
- 64 位累计值溢出时会饱和到 `UINT64_MAX`，不会回绕。

## 连接明细

在主表中选中一个进程后右键，选择“查看连接明细”可打开该进程实例（PID + 创建时间）的连接明细窗口。每个进程实例最多只有一个明细窗口；再次打开会激活已有窗口，而不同进程实例可同时各自打开一个窗口。

明细窗口使用下列 12 列：

| 列 | 含义 |
|---|---|
| 状态 | `活跃`、`历史` 或 `进程已结束` |
| 方向 | `上行`、`下行` 或 `双向` |
| 传输层协议 | TCP 或 UDP |
| 推断应用协议 | 仅按端口推断的应用协议标签 |
| 本地地址 | 本机 IPv4 或 IPv6 地址 |
| 本地端口 | 本机端口 |
| 远端地址 | 对端 IPv4 或 IPv6 地址 |
| 远端端口 | 对端端口 |
| 上行累计 | 该连接已发送的累计 IP 字节数 |
| 上行速度 | 当前发送速率 |
| 下行累计 | 该连接已接收的累计 IP 字节数 |
| 下行速度 | 当前接收速率 |

IPv4 使用标准点分十进制格式，IPv6 使用 Windows 的标准文本格式。发送事件把源端点规范为本地端点、目的端点规范为远端端点；接收事件则把目的端点规范为本地端点、源端点规范为远端端点。因此同一条连接的双向事件会合并成同一行。连接键由进程实例、传输层协议、推断应用协议、本地 IP:端口和远端 IP:端口组成；PID 被复用时不会与已有进程实例合并。清零前重新出现同一连接键会继续聚合到同一行，本程序不追踪 TCP 序列号或独立会话 ID。

“活跃”表示最近五秒内收到过该连接的事件；超过五秒仍保留为“历史”。进程已退出时，行保留并显示“进程已结束”。TCP 和 UDP 分别显示在“TCP 列表”和“UDP 列表”页签中；两个列表分别保存自己的排序、滚动位置和选择项。窗口初始按上行和下行速度之和降序排列；点击任一列头按该列升序排列，再次点击同一列切换为降序。每次新建明细窗口后的首次快照会显示 0 速率，随后按相邻快照的实际单调时间间隔计算速率；重复打开同一进程实例只会激活已有窗口，不会重置其速率基线。

明细窗口的“IP 筛选”会对本地和远端 IPv4/IPv6 的当前格式化文本进行不区分大小写的包含匹配；空值不限制结果。“端口筛选”会先忽略首尾空白，再对本地和远端端口的显示文本进行包含匹配，例如输入 `990` 可匹配 `990`、`4990` 或 `9900`；非空输入必须是 `0` 至 `65535` 的十进制数字，无效输入不会作为筛选条件，界面会提示错误。IP 和端口筛选条件同时作用于 TCP、UDP 两个页签，筛选立即重建显示并自动置顶，不影响后台累计、速率基线或其他进程的明细窗口。明细窗口的“导出 CSV”只导出当前页签内当前筛选、当前排序后的全部可见行，文件使用 UTF-8 BOM。

两个列表都会在当前排序列显示原生排序箭头，并遵循相同的置顶/手动位置保持规则：筛选或重新排序后自动置顶，手动滚动离开顶部后保留稳定的顶部行和选择项，回到第一行后恢复自动置顶。

## 进程总网速

主窗口状态栏显示“进程总网速：↑ … ↓ … 合计 …”，其数值是主进程统计中所有已采集进程当前上下行速度之和。进程名筛选只改变列表显示，不改变该合计。这个口径不会重复累计 Hyper-V、网卡绑定或隧道等多层网络接口，但未被 ETW 成功捕获、无法归属到进程或已经丢失的事件不会计入，因此它不是整台服务器网卡线速。

“清零统计”同时清空主表与连接明细的历史、累计值、速率基线和“明细丢弃”计数，但不停止采集。连接明细全局最多保留 100000 个不同连接键；达到上限后，新连接键的事件会被丢弃并计入状态栏的“明细丢弃”，已有连接仍继续累计。状态栏的“事件丢失”（`EventsLost`）、“实时缓冲区丢失”（`RealTimeBuffersLost`）、“解析失败”和“明细丢弃”是四个独立计数，彼此不相加；任何非零 ETW 丢失计数都表示累计流量可能只是实际流量的下界。

应用协议是端口推断，不检查报文内容。发送事件优先使用目的端口，接收事件优先使用源端口；首选端口未命中时才尝试另一端端口，因此端口复用时推断结果可能不符合实际应用协议。

## 端口协议推断

“HTTPS/TLS”、“QUIC”、“DNS”等标签都是端口推断，不是对报文内容或 TLS 握手的识别。发送事件优先使用目标端口，接收事件优先使用源端口；首选端口未命中时才尝试另一端口。

| 传输层/端口 | 推断协议 |
|---|---|
| TCP 20/21 | FTP |
| TCP 22 | SSH |
| TCP 25/465/587 | SMTP |
| TCP/UDP 53 | DNS |
| UDP 67/68 | DHCP |
| TCP 80 | HTTP |
| TCP 110/995 | POP3 |
| UDP 123 | NTP |
| TCP 143/993 | IMAP |
| TCP 389/636、UDP 389 | LDAP |
| TCP 443 | HTTPS/TLS |
| UDP 443 | QUIC |
| TCP 445 | SMB |
| UDP 500/4500 | IPsec/IKE |
| TCP 1433 | SQL Server |
| TCP 3306 | MySQL |
| TCP/UDP 3389 | RDP |
| TCP 5432 | PostgreSQL |
| TCP 6379 | Redis |
| TCP 27017 | MongoDB |

非标准端口、端口复用、隧道和加密内层协议可能被推断为错误协议或“其他”。

## 已知限制

- 极高事件率或系统资源不足时 ETW 可能丢失事件，程序只能显示计数，不能补回。
- 为避免对每个网络事件执行完整进程查询，已识别进程只校验创建时间；查询暂时失败或进程不可访问时，每 8 个该 PID 的事件重试一次完整查询。恢复到可读取的真实创建时间后会识别更新；同一 PID 上两个始终不可访问的连续进程生命周期仍可能被合并，因为仅凭网络事件无法取得进程创建时间。
- 如果停止私有 ETW 会话时系统返回非完成型错误，程序会保留该会话的控制所有权并拒绝创建新会话；按钮显示“重试清理”，点击后重试停止，成功后才可重新开始采集。停止失败的错误码优先显示，最近错误会保留用于排查。
- NetAssess 只允许一个实例运行，并使用固定的专用 ETW 会话名。启动返回错误 1450 或发现同名会话时，程序只枚举并清理名称严格匹配当前 NetAssess 会话或旧版 `NetAssess-进程号-GUID` 格式的遗留会话，然后重试一次；不会停止其他软件的 ETW 会话，也不会修改 `EtwMaxLoggers`。若其他软件仍占满系统记录器槽位，采集保持停止并显示 Windows 错误码。
- 管理员权限是启动和 ETW 采集的前提，但不保证可以读取受保护进程的路径或结束受保护进程；这类操作会保留 Windows 的访问控制并报告错误码。
- 程序仅提供实时 GUI、当前可见结果的 CSV 导出；不提供历史恢复、曲线图、数据库、远程管理、按网卡拆分展示或报文深度解析。
